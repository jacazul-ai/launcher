# Jacazul Launcher Manifesto

Repository mandates for agents working on the Jacazul Launcher. Workflow,
persona and response rules live in the `jacazul-engine` skill; this file keeps
what no skill carries and names where the rest lives.

## 🏛 Architectural Boundaries

- **Setup (`scripts/configure`):** one-time, immutable preparation:
  directories, symbolic links in `~/bin`, initial templates.
- **Runtime (`scripts/bootstrap/`):** per-session and mutable: environment
  variables, surgical settings JSON updates, locating system resources such
  as the real `task` binary.

## 🔊 Logging Philosophy

"Silent by Default": healthy runs and verification of existing resources
print nothing unless `DEBUG=true`; state changes always print ("Creating
directory X"); errors go to `stderr` with instructional context. `DRY=true`
runs the whole bootstrap without starting the CLI binary.

## 🔒 Engineering Mandates

1. **Taskwarrior Abstraction:** agents and tools MUST NOT invoke the raw `task` binary directly. Use `taskp` or `tw-flow`, and preserve project
   isolation through `TASKDATA`. If an agent meets the `scripts/task`
   wrapper, it stops and consults the user. `rtask` is a manual,
   administrative bypass only.
2. **Hatch-Generated Skills (CRITICAL):** the `jacazul-engine` skill and all
   agent prompt files are generated by `jacazul-hatch` from
   `jacazul/hatch/templates/`. NEVER edit generated files directly; edit the
   templates and regenerate with `jacazul-hatch --target <target>`
   (`--client` is a compatibility alias; `pi`, `openai` and `all` are
   targets too). Generated: `skills/jacazul-engine/SKILL.md` (the hub, from
   `gemini_full.md`), `skills/jacazul-engine/references/` and
   `agents/{persona}-{client}.md` for Copilot and Opencode. Hand-written and
   tracked: `skills/jacazul-engine/evals/`. `scripts/bootstrap/hatch` picks
   the runtime target; client bootstraps link and configure.
3. **Skill Authoring:** any new skill, or any change to a skill's
   description, body structure or cross-references, follows
   [`docs/skill-methodology.md`](docs/skill-methodology.md). It governs how a
   skill is written, not repository policy or the workflow.
4. **Context Preservation:** closing a task without documentation is
   FORBIDDEN. `tw-flow done` requires an `OUTCOME:` annotation; discarded
   tasks carry an automatic audit record.
5. **Generic by Default:** skills, scripts, docs and proposals use or
   propose generic tooling that works the same in every harness: shell,
   project scripts, open protocols and open MCP servers. A vendor- or
   harness-specific tool is allowed only for an extremely specific need
   that no generic tool covers; state that need and get operator approval
   before using or proposing it. When a tool or measurement exists for one
   harness only (the eval runner is Claude Code's), say which harness the
   result covers.

## 🧠 Session Stabilization

1. **Multi-Agent Diagnostic Loop:** a diagnosis produced by one agent is
   re-interpreted, validated and implemented by the session navigator before
   acting, so the root cause is checked from two perspectives.
2. **Tool-Agnostic Resilience:** when create or edit tools are unavailable,
   use base system primitives (`cat >`, `touch`, `echo >>`) and verify the
   change with `ls` or `cat`.
3. **Horizontal Skill Architecture:** activate skills directly and
   independently; one skill never activates another, so a failing subsystem
   does not blind the agent.
4. **The Keystone Pattern:** `jacazul-engine` and `taskwarrior-expert` load
   in the first turn, in parallel with `tw-flow focus`. `git-expert` and
   `security-expert` load on demand: git-expert before the first repository
   operation, security-expert when the work touches CI, secrets,
   dependencies or publishing (measured in `docs/skill-evals.md`). Mandates
   in a loaded skill take precedence over generic system prompts.

## 🧬 Interaction Standards

- **Context first:** never ask the user for state the system holds. When and
  how to orient: `jacazul-engine` hub, "Context Orientation".
- **Task references:** by 8-character UUID, never numeric IDs, and never a
  UUID alone: `uuid description [plan-name]` (abbreviated descriptions are
  fine), e.g. `f519b8c5 Define backlog UDA schema [tw-flow-backlog]`.
- **Task completion announcement:** "Terminei a tarefa <uuid> <desc> [<plan>],
  começa com <uuid> <desc> [<plan>]". The user works across several plans.
- **Persona and language:** answer in the active persona and the session
  language; persistent data stays in English. `jacazul-engine` hub, "Persona
  Protocol".
- **Tool banners as mandates (Prompt as Ad):** `jacazul-engine` hub, "Core
  Principles".

## 🎓 Core Lessons Learned

- **Behaviour Enforcement:** system integrity comes from "vaccinating"
  tools: a workflow bypass (raw `task` instead of `taskp`) is intercepted
  with tactical guidance instead of a bare failure.
- **Error as Prompt (for script authors):** workflow and control scripts
  never just fail; their `stderr` tells the agent what to do next ("Stop and
  consult the user", "Intent mismatch: use X instead of Y").
- **Test-First:** bug fixes and features start with a reproduction test that
  fails in the current environment.
- **Running the Suite:** the only invocation is `make test`; do not improvise
  `python -m unittest discover`. Its `-t .` keeps the relative imports in
  `tests/` working and its explicit `-p '*test*.py'` collects `*_test.py`
  files. `tests/test_suite_contract.py` pins it. The Go launcher
  (`cmd/jacazul`) runs with `make go-test` until the Python cutoff, when
  `make test` becomes the Go suite.

## Git Workflow

Pinned for `git-expert` and `git-mode`: topic work is rebased onto the
reference branch and fast-forwarded, so history stays linear.

- integration: linear
- reference: master

## 📚 Documentation Mandate

- **Order:** Implementation → Test → Docs; all three before `tw-flow done`.
- **Scope:** any feature, command, flag or behavior visible to the user is
  reflected in the matching doc. Before proposing `tw-flow done`, ask: "Does
  this change user-facing behavior? Which doc needs updating?"
- **Which doc:** the map and the writing rules (Trigger → Action for every doc
  except ARCHITECTURE) are in [`docs/README.md`](docs/README.md).

## 🐊 GitHub Broker

- **Protocol:** agents never handle raw GitHub tokens or ask for credentials.
  `jacazul-broker` (or `jacazul.cli.broker`) is the sole authority for GitHub;
  credentials resolve Project > Org > User through `cryptozoid` and
  `vault.json`. Sync issues with `jacazul-broker sync #ID`.
- **Platform testing:** experimental, POC or non-production broker operations
  target `jacazul-ai/jacazul-ai-sandbox`; never create test issues, labels or
  milestones in `launcher`.
