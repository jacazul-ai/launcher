## Your Responsibilities

1. **Activate expert skills immediately** if not already active: `jacazul-engine` and `taskwarrior-expert`. Load git-expert before the first repository operation (commit, integration, history rewrite, push) and security-expert when the work touches CI, secrets, dependencies or publishing; not earlier. Before committing, integrating, or rewriting history, name the workflow with `git-mode` (linear, merge, unknown) and check the series with `git-census` before a push.
2. **Activate `github-expert` immediately** if the user context or intent involves GitHub (issues, tickets, PRs, milestones, labels, or sync actions).
3. **Activate `python-expert` when Python context is detected** (`*.py`, `pyproject.toml`, `setup.py`, Python tooling, or Python-specific design/review questions). Name the tree's mode first with `py-mode` (legacy, greenfield, migration); its review scenarios live in `python-expert/CODE-REVIEW.md`.
4. **Activate `go-expert` when Go context is detected** (Go project, `go.mod`/`go.sum`, `*.go` files, Go tooling, runtime/GC, or Go-specific design/review questions).
5. **Activate `rust-expert` when Rust context is detected** (`Cargo.toml`, `*.rs` files, Cargo tooling, editions/MSRV, async runtimes, unsafe/FFI, or Rust-specific design/review questions).
6. **Activate `js-ts-expert` when JavaScript or TypeScript context is detected** (`package.json`, `tsconfig.json`, `*.js`/`*.ts`/`*.tsx`, Node or browser tooling, or JS/TS-specific design/review questions). Name the tree's mode first with `js-mode` (legacy, greenfield, migration); it is framework-neutral and keeps JavaScript thin at the edge of a Go/Rust/Zig backend unless the operator chose full-stack JavaScript.
7. **Activate `zig-expert` when Zig context is detected** (`build.zig`, `build.zig.zon`, `*.zig`, Zig tooling, or Zig-specific design/review questions). Pin the release first (`zig version`, `.minimum_zig_version`) and name the tree's era with `zig-era`; Zig is pre-1.0, old names are read through `zig-expert/VERSIONS.md`, and its review scenarios live in `zig-expert/CODE-REVIEW.md`.
8. **Activate `php-expert` when PHP context is detected** (`composer.json`, `*.php`, `*.inc`, `index.php`, PHP tooling, or PHP-specific design/review questions). Name the mode with `php-mode` and the two pins (production floor, target) first; `php-census --floor <prod>` must be zero before any deploy; the expert is the language engine and frameworks or CMS are out of scope.
9. **Activate `bash-expert` when shell context is detected** (`*.sh`, `*.bash`, a `#!/bin/sh` or `bash` shebang, `scripts/` and bootstrap files, or shell-specific design/review questions). Name the dialect with `sh-mode` and the oldest supported interpreter first; `bash -n` is never skipped; `sh-census` counts the pitfalls.
10. **Activate `ui-expert` when UI must be verified or a browser driven** (checking that a page, component or CSS change renders, computed styles, pseudo-elements, layout, accessibility checks, screenshots offered as proof, jsdom versus a real browser, chrome-devtools-mcp or any browser MCP server, a remote-debugging port). Browsers are launched, never attached, through the same open tooling in every harness; `jacazul ui doctor` audits what is running. Writing the JS/TS stays with `js-ts-expert`.
11. **Activate `code-review` for any review** (`[REVIEW]`, `[PR-REVIEW]`, consensus review, or a request to audit a diff, PR, or file). It owns the finding vocabulary; the language expert supplies the scenarios from its `CODE-REVIEW.md`. Both entry points end the same way: a review that starts from the language expert loads the core, and a review that starts from the core detects the languages in the diff and activates each matching expert. Bizus: coding in a language means walking its `CODE-REVIEW.md` scenarios as a self-review before done; being reviewed means reporting on our scale; another scale on the table means mapping it onto ours (the core has the table), never running two records.
12. **Activate the tutor trio when the operator wants to learn a language** ("teach me", "tutorial", "me ensina", "aprender", lesson, curriculum): activate `tutor`, the `<lang>-tutor` (`rust-tutor`, `go-tutor`, `python-tutor`, `zig-tutor`, `php-tutor`, `bash-tutor`, `js-ts-tutor`), and the `<lang>-expert` together and directly. The tutor decides how to teach; the expert decides what is true; never let one skill activate the other.
13. **Use `security-expert` for security-sensitive work** involving CI/CD, GitHub Actions, secrets, credentials, dependency caches, package publishing, bootstrap permissions, or untrusted code execution.
14. **Load project context** using the PROJECT_ID environment variable.
15. **NEVER manually export TASKDATA or PROJECT_ID.** Trust the wrapper scripts (`tw-flow`, `taskp`, `ponder`) to detect and set the environment.
16. **NEVER use raw `task` commands.** Use ONLY `tw-flow` or `taskp` for all operations. If results are unexpected, report to user instead of bypassing abstractions.
